# Student Bursary Claims Management System

A full-stack MERN application developed for ICE Task 1.

The system allows students participating in a university bursary programme to submit, view, and cancel bursary claims for work they have completed.

## Technologies Used

- MongoDB
- Express.js
- React
- Node.js
- Mongoose
- Vite

## Features

### Submit Claim

Students can submit a claim by providing:

- Student Number
- First Name
- Surname
- Hours Worked

The hourly rate is fixed at R200.00.

The backend automatically:

- Sets the hourly rate to R200.00
- Calculates the total claim amount
- Generates the claim ID
- Records the submission date
- Sets the initial claim status to Pending

### View Claims

Students can search for their claims using their Student Number.

Only claims submitted during the previous 12 months are returned.

The system displays:

- Claim ID
- Student Number
- Date Submitted
- Hours Worked
- Hourly Rate
- Total Claim Amount
- Status

### Cancel Claim

Students can cancel a claim only when its status is Pending.

Approved, Rejected, and already Cancelled claims cannot be cancelled.

The cancellation business rule is enforced by the backend.

## Validation Approach

Validation is implemented at both the frontend and backend levels.

The React frontend provides immediate feedback to the user and prevents basic invalid submissions.

The Express API performs server-side validation before processing a claim. Mongoose schema validation is also used to enforce data requirements at the database model level.

The following rules are validated:

- Student Number is required and cannot exceed 20 characters.
- First Name is required and cannot exceed 50 characters.
- Surname is required and cannot exceed 50 characters.
- Hours Worked is required and must be greater than zero.
- The Hourly Rate is assigned by the server and is fixed at R200.00.
- The Total Claim Amount is calculated by the server.
- The Date Submitted is generated by the server.
- New claims are assigned a Pending status.
- Only Pending claims may be cancelled.

This layered validation approach ensures that business rules are not dependent only on frontend validation.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/claims` | Submit a new claim |
| GET | `/api/claims/student/:studentNumber` | Retrieve a student's claims from the previous 12 months |
| PATCH | `/api/claims/:claimId/cancel` | Cancel a Pending claim |

## HTTP Status Codes

The API uses appropriate HTTP status codes, including:

- `200 OK` - Successful request
- `201 Created` - Claim successfully created
- `400 Bad Request` - Validation failure
- `404 Not Found` - Claim not found
- `409 Conflict` - Claim cannot be cancelled
- `500 Internal Server Error` - Unexpected server error

## Running the Application

### Backend

Navigate to the backend folder:

    cd backend

Install dependencies:

    npm install

Create a `.env` file containing:

    PORT=5000
    MONGO_URI=your_mongodb_connection_string

Start the backend:

    npm run dev

### Frontend

Navigate to the frontend folder:

    cd frontend

Install dependencies:

    npm install

Start the frontend:

    npm run dev

The frontend will normally be available at:

    http://localhost:5173

The backend runs at:

    http://localhost:5000

## Security

Sensitive configuration values such as the MongoDB connection string are stored in the `.env` file.

The `.env` file and `node_modules` directories are excluded from Git using `.gitignore`.
